## 0. 定位

不是「课表 App 加几个页面」，而是**本地优先的校园数据工作台**：

- 唯一核心资产 = **一套金智 SSO 会话**（sidportal.buct.edu.cn → 各子系统），登录一次打穿全部域
- 业务真相 = 本地规范化快照（带来源与时间），不是实时学校状态
- 界面只读快照，不自己抓数据

THEIA-Android 用 Capacitor 做壳，死在「WebView 的 CAS Cookie 交给原生 HTTP」这一步，README 明写已废弃。
我们反过来：**原生持有会话，WebView 只在登录兜底时出现**。

## 2. 数据模型（Kotlin 骨架）

    enum class RefreshState { FRESH, STALE, EMPTY_CONFIRMED, FAILED_FALLBACK, NEVER }

    data class Provenance(
        val source: String,          // "jwglxt" / "theol" / "imap"
        val capturedAt: Long,        // 抓取时刻（毫秒）
        val parserVersion: Int,      // 解析器版本，页面改版时递增
        val refreshState: RefreshState,
        val complete: Boolean        // 分页/权限受限时置 false
    )

    /** 每个数据域都套这一层：data 可为 null，语义靠 provenance 区分 */
    data class DomainSlice<T>(
        val data: T?,
        val provenance: Provenance,
        val lastError: String? = null
    ) {
        val isEmptyConfirmed get() = provenance.refreshState == RefreshState.EMPTY_CONFIRMED
        val isUsable get() = data != null && provenance.refreshState != RefreshState.NEVER
    }

    data class CampusState(
        val profile:      DomainSlice<StudentProfile>,
        val schedule:     DomainSlice<CourseTable>,
        val grades:       DomainSlice<List<GradeRow>>,
        val exams:        DomainSlice<List<ExamRow>>,
        val progress:     DomainSlice<AcademicProgress>,
        val theolCourses: DomainSlice<List<TheolCourse>>,
        val assignments:  DomainSlice<List<Assignment>>,
        val notices:      DomainSlice<List<Notice>>,
        val mail:         DomainSlice<List<MailSummary>>,
        val calendar:     DomainSlice<AcademicCalendar>,
        val emptyRooms:   DomainSlice<List<RoomSlot>>,
        val venues:       DomainSlice<List<VenueSlot>>
    )

**三条硬规矩**（THEIA 踩过的坑）：
1. data == null 且 refreshState == NEVER ≠ 学校没有数据
2. data 为空且 EMPTY_CONFIRMED 才是「确认没有」
3. 抓取失败 → 保留旧快照，refreshState 降为 FAILED_FALLBACK，界面标注「数据来自 X 时刻」

## 5. 企业微信接入

先抓包确认是哪一种，两条链路实现完全不同：

| | A. 学校自建（如 qy.buct.edu.cn） | B. 腾讯企业微信标准版 |
|---|---|---|
| 域名 | 学校自有域 | open.work.weixin.qq.com |
| 登录 | 通常走学校 SSO 换 ticket，**可复用已有会话** | 扫码/手机验证，独立凭据 |
| 能接 | 通知、待办、审批列表、通讯录只读、校历、班车 | 应用消息、待办、日程 |
| 存储 | 会话 Cookie（内存 + EncryptedSharedPreferences） | corpId/secret 或 OAuth token |
| 合规红线 | 不代打卡、不代审批、不自动回复 | 同左 |

抓包要点：
1. 在企业微信里打开一个学校应用，看 URL 域名
2. 出现 /sso/ 或 ticket= 参数 → 走 SSO 换票，能复用会话
3. 只有扫码 → 需单独登录态，做好双会话并存
4. 记录 XHR 的 Referer / Cookie / X-Csrf-Token，这些决定能否直连

架构预留：M3 时把 CampusSource 做成可插拔，企业微信只是再加一个 wecom/WecomSource.kt，不动其它层。

## 6. 工程与风险

### 模块化
先不拆 module（单 app + 包级隔离）；等 M3 代码过 3 万行再拆 :core/:data/:feature。理由：AGP 9 + 云端 CI 下多 module 显著拉长构建。

### CI
- 现有 build-apk.yml 可用（临时签名 + Release）
- 新增：体积门禁（APK > 12MB 直接 fail）、parserVersion 变更提醒
- 「构建失败即删提交与 run 记录」的约定保持

### 安全

| 数据 | 存放 |
|---|---|
| 学号/密码 | 绝不落盘，只在登录瞬间使用 |
| SSO Cookie | EncryptedSharedPreferences + Keystore |
| WebAuthn 凭据 | Android Keystore（指纹/生物识别） |
| 日志 | 域名与学号脱敏 |
| 网络 | 现有 BuctTlsTrustManager 固定校方证书链 |

### Top 8 风险

| # | 风险 | 缓解 |
|---|---|---|
| 1 | 教务页面改版导致解析全崩 | parserVersion + 宽松解析 + 保留旧快照 |
| 2 | 登录接口变更（SM2 公钥轮换） | 公钥可远程更新，失败时降级 WebView 兜底 |
| 3 | THEOL 无公开 API | 只读页面解析，标识 complete=false |
| 4 | 体积失控 | 每阶段体积门禁 |
| 5 | 单人维护超载 | 阶段严格串行，M1 不完不进 M2 |
| 6 | 学校风控 | 请求限速、随机抖动、非爬虫 UA |
| 7 | 企业微信需扫码 | 接受双会话，不强行合并 |
| 8 | GPL 合规 | 保持 GPL-3.0，保留 upstream 版权声明 |
