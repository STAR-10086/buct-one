# BUCT One · 北化一站 — 路线规划

> 适用基线：`v0.3.2`（`versionCode = 7`，包名 `com.buct.one`）｜单 module Kotlin + Jetpack Compose（液态玻璃 UI）
> 工程基线：`compileSdk android-37.0` / `build-tools 37.0.0` / JDK 21 · 全云端 GitHub Actions CI · APK 硬门禁 100MB（80MB 预警）

---

## 一、现状基线（截至 v0.3.2）

### 1.1 已落地功能域与能力矩阵

| 模块 / 域 | 代码位置 | 认证与网络方式 | 当前已落地能力 |

### 1.2 核心工程底座

- **跨模块无感续期**：`SsoSilentRelogin` 单飞协调统一身份认证静默重登，失败冷却与密码变更即擦除机制并存。
- **单向分层与 CI 门禁**：`ui → store/session/model`、`sync → source/store/session`、`source/*` 互不依赖、`model` 零外部 `import`；`check.yml` 强制扫描越层依赖与 TLS 校验。
- **分发与自动更新**：GitHub Release + Cloudflare R2 双源分发（`update.buct.one` / `dl.buct.one`），支持冷启动与「我的」页手动检查更新、ABI 匹配及 SHA-256 + 证书签名双重校验。

## 二、后续演进规划（v0.4.x → 长期）

### 阶段一：高频刚需补齐与主动提醒（建议 v0.4.0）

1. **北化在线课件资料 + 校内通知聚合**
   - 补齐 `TheolSource` 对课程「教学资源 / 课件目录」的只读浏览、目录展开与原生下载打开（复用现有 `FileProvider`）。
   - 汇总教务通知、北化在线课程公告与重要未读邮件，形成统一消息聚合入口与工作台提醒。
2. **轻量本地智能提醒（`WorkManager` + 通知渠道）**
   - 基于本地缓存与低频周期刷新，支持可独立开关的提醒策略：作业 DDL 临期（如提前 24h / 3h）、考试倒计时、校园卡余额低于阈值、重要新邮件提醒。
   - 兼顾国产 ROM 后台限制：不强求常驻保活，依赖本地已同步 DDL 的定时触发 + 前台/充电时段增量同步兜底。
3. **桌面小组件全家桶扩展**
   - 复用现有 HyperOS / OriginOS 无标题玻璃小组件框架与按 `appWidgetId` 隔离持久化方案，新增：
     - **DDL / 考试倒计时小组件**（同尺寸 `2×2` / `4×2`）
     - **校园卡余额 + 未读邮件迷你信息卡小组件**

### 阶段二：校园生活新域拓展（v0.4.x / v0.5.0）

> 所有新域严格执行「先浏览器/脚本只读探明认证与接口协议 → 评估可行性与体积影响 → 再原生接入」流程。

1. **校园网账号与流量余量**
   - 调研学校深澜自服务 / Portal 接口（`tree.buct.edu.cn` 等）：展示已用/剩余流量、账户余额、在线终端数，并评估下线终端管理与工作台状态卡。
2. **图书馆借阅与续借**
   - 调研北化图书馆 OPAC / 统一身份认证衔接方式：在借图书清单、应还倒计时提醒、一键续借。
3. **宿舍电费余量查询**
   - 调研校内购电 / 企微应用 H5 的 SSO 链路与只读余额查询接口；若存在稳定的 CAS → H5 免扫码换票路径，则做原生剩余电量与预警展示（不支持替代支付）。
4. **班车时刻表与场馆预约余量**
   - 东区 ↔ 昌平校区通勤班车下一班倒计时（本地内置时刻表，区分工作日/周末/寒暑假，轻量零网络依赖）。
   - 体育场馆空闲时段/余量只读展示（先确认公开或 SSO 只读页面结构稳定性）。

### 阶段三：体验深挖与本地数据分析

1. **学业分析与校历校准增强**
   - 成绩页支持「目标 GPA 试算」与重修/未修课程学分缺口统计（结合培养方案归类）。
   - 校历教学周进度条与重要节假日/考试周倒计时，减少人工校准周次成本。
2. **校园卡消费洞察**
   - 基于本地已同步流水，使用纯 Compose `Canvas` 绘制月度支出趋势与时段/商户类别（食堂 / 超市 / 洗浴等）汇总，不引入额外第三方图表库，严守 APK 体积预算。
3. **校园邮箱按需增强**
   - 保持当前轻量收件定位，按实际使用反馈考虑补充：星标/红旗标记、按发件人/仅含附件筛选，以及视需要评估极简快速回复。

### 持续工程基建（贯穿各阶段）

- **数据域解析器回归测试**：目前 `app/src/test/` 已覆盖正方教务与液态玻璃 UI 几何逻辑，后续为 `data/source/{card,mail,scs,sjcx,theol,tygl}` 6 个纯函数 `Parser` 各自补齐脱敏 HTML/JSON 样本与离线 JUnit 单测，并在 `.github/workflows/check.yml` 自动执行（改动前先确保无 PII 泄露）。
- **CI 维护与升级**：将 `.github/workflows/*.yml` 中的 `actions/checkout`、`actions/setup-java`、`actions/cache` 等迁移至支持 Node.js 24 的最新版本，消除弃用警告并持续优化 Gradle 构建缓存。

## 三、开发准入规范与「不做」清单

### 新模块接入自查表
1. **认证**：必须全原生 Kotlin + OkHttp，禁止引入 WebView 登录流程。
2. **分层**：严格遵守 `model（零 import）← store ← source（子包隔离）← sync ← ui`，合入前过 `check.yml` 静态检查。
3. **铁律**：失败永不覆盖旧 `data`、`NEVER != EMPTY_CONFIRMED`、改解析器必递增 `parserVersion`、更新时间戳 `capturedAt` 单调不减。
4. **安全与体积**：全走 `BuctTlsTrustManager` + `BuctDns`；独立凭据必须用独立 `KeystoreCipher` alias 并列入 `backup_rules.xml` / `data_extraction_rules.xml`；严控依赖增量以防触发 80MB 预警 / 100MB 门禁。

### 明确「不做」边界
- **不做 WebView 登录或跨端 Web 壳**（Capacitor / RN 等）。
- **不做无人值守全自动抢课或高风险自动化写操作**（如代打卡、代交答案、自动抢购），仅保留合规查询、手动确认操作与本地闹钟/通知提醒。
- **不做任何第三方行为埋点、崩溃上报 SDK 或广告组件**。
- **不引入高体积离线大模型 / OCR / 重型地图 SDK**，保持客户端轻量、快速启动与可控包体。
