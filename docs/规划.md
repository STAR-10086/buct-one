## 0. 定位

不是「课表 App 加几个页面」，而是**本地优先的校园数据工作台**：

- 唯一核心资产 = **一套金智 SSO 会话**（sidportal.buct.edu.cn → 各子系统），登录一次打穿全部域
- 业务真相 = 本地规范化快照（带来源与时间），不是实时学校状态
- 界面只读快照，不自己抓数据；**架构上不存在写路径**，不是靠 UI 约定

THEIA-Android 用 Capacitor 做壳，死在「WebView 的 CAS Cookie 交给原生 HTTP」这一步。
我们反过来：**原生持有会话，WebView 只在登录兜底和企微换 Cookie 时出现一次**。

## 3. 数据层（M2 落地，详设见 plan-1）

### 3.1 SSO 会话复用链路

~~~text
[A] sidportal.buct.edu.cn    GET /login?service=<target>  拿 execution + AES key
                             POST 密码（AES-ECB-PKCS7 → base64）
                             → 302 jwglxt.../sso/jziotlogin?ticket=ST-xxxx
                             → 落 CASTGC/TGT（HttpOnly）
[B] jwglxt.buct.edu.cn       GET /sso/jziotlogin?ticket=... → 302 /xtgl/index_initMenu.html
                             → 落 JSESSIONID（约 30 分钟无操作过期）
[C] theol.buct.edu.cn        受保护页 → 302 sidportal（带 TGT）→ 302 回 theol 落自己的 JSESSIONID
                             此后同域免二次登录
[D] venue                    免登录公开页直抓
~~~

- **Cookie 池化**：`PooledCookieJar`（按 host|path 分池，内存为唯一运行时真相，加密落盘去抖 500ms）
- **失效探测只打最轻页**：jwglxt `/xtgl/index_initMenu.html`、theol `/meol/common/index.jsp`；302→login 即失效。不做定时轮询，只在「即将用」之前探测
- **状态机**：ACTIVE → PROBING → EXPIRED → RENEWING → ACTIVE；`UNAUTHORIZED`（凭据错）/ 风控 各自独立出口
- **静默续期**：`SessionRenewerAdapter` 把现有回调式 `utils/SessionRenewer.kt` 包成 `suspend fun`，旧代码零改动；重登并发在既有 coordinator 内排队
- **10 分钟新鲜窗口**：距 `lastConfirmedAt` < 10min 直接放行，不探测

### 3.2 CampusSource 接口

~~~kotlin
interface CampusSource<T : Any> {
    val domain: CampusDomain
    val sourceId: String        // 如 jwglxt.schedule，进 provenance
    val parserVersion: Int      // 改解析必须 +1
    suspend fun fetch(session: SsoSessionManager): RawSource   // 内部分页
    fun parse(raw: RawSource): T                               // 纯函数：无时钟/随机/IO
    fun validate(value: T): Completeness
}

sealed class CampusError(open val message: String) {
    class Network(...)     // 退避重试
    class Auth(...)        // 不退避，直接停
    class Parse(..., val parserVersion: Int)   // 保留旧快照 + 计数
    class RateLimited(...) // 直接跳到最大退避 6h
    class Incomplete(...)  // 抓到了但不完整，complete=false
}
data class Completeness(val complete: Boolean, val reason: String?,
                        val expectedCount: Int?, val actualCount: Int)
~~~

- **JwglxtSource** 是门面：复用既有 `AcademicHttpTransport` / `ZfAcademicAdapter` / `AcademicStudyParser`，不新写 HTTP 层。JqGrid 分页 `rows=100`，页间 300~600ms 随机抖动；`records != 累计条数` 即 `complete=false`
- **TheolSource** 用 **Jsoup**（已在依赖）做轻量选择器解析，不用正则（E6）

### 3.3 provenance 与不变式

~~~kotlin
@Serializable enum class RefreshState { FRESH, STALE, EMPTY_CONFIRMED, FAILED_FALLBACK, NEVER }

@Serializable data class Provenance(
    val source: String,        // sourceId
    val capturedAt: Long,      // epoch ms
    val parserVersion: Int,
    val refreshState: RefreshState,
    val complete: Boolean,
)
@Serializable data class DomainSlice<T>(val data: T?, val provenance: Provenance, val lastError: String? = null)
~~~

**六条不变式**（`CampusStore.commit` 落盘前强制校验，违反即拒绝）：

| # | 不变式 |
|---|---|
| I1 | `NEVER` ⟺ 该域从未成功抓取（data 必 null） |
| I2 | data == null 且 state != NEVER → 允许，但 lastError 必非空 |
| I3 | complete == false → 原因必须可追溯到 Completeness，且 UI 可见 |
| I4 | capturedAt 单调不减（时钟回拨保护） |
| I5 | **失败永不产生新 data**：失败路径只改 refreshState/lastError，data 原样保留旧值 |
| I6 | parserVersion 只增不减 |

**改版检测（StructureProbe）**：每 source 声明 2~5 个关键特征，分 FATAL/DEGRADE 两级。
FATAL 挂 → 抛 `CampusError.Parse` → 该域 FAILED_FALLBACK，**旧快照原样保留**（THEIA 最大的坑就是改版后清空数据）。
DEGRADE 挂 → 照常解析但 `complete=false` + UI 标注。连续 3 次 Parse 失败 → 首页提示「学校页面疑似改版」。

### 3.4 CampusStore 选型：分片 JSON（已拍板）

| 方案 | 体积 | 结论 |
|---|---|---|
| DataStore(Proto) | 0 | 否：schema 改动要 proto 编译，云端 CI 下是额外故障点 |
| Room | +300KB | 否：数据是只读快照，无跨域 JOIN 需求 |
| **分片 JSON + kotlinx.serialization** | +150KB | **是**：每域一文件 → 天然失败隔离；temp+rename → 天然原子；演进换文件名，不写迁移 |

目录：`filesDir/campus/<account>/` → `manifest.json`（分片索引 + sha256）+ `jwglxt.schedule.v3.json` + `.trash/`（保留 3 份 FIFO）

commit 原子序列：校验 I1~I6 → 写 `<file>.<uuid>.tmp` → 算 sha256 写新 manifest.tmp → `renameTo` → 旧片移 `.trash/`。
冷启动自检：sha256 不符 → 丢弃该分片 → 从 `.trash/` 恢复上一个好版本 → 仍不行则该域 FAILED_FALLBACK 初始化。读路径无锁（文件不可变 + rename 原子性）。

### 3.5 SyncEngine

- **并发度 = 1**（登录域串行）。理由：学校风控是主要矛盾；单人 App 无吞吐诉求；串行让限速与退避一目了然。唯一例外 VENUE（免登录）可并行
- **退避**：指数 60s → 6h。Auth 不退避直接停；RateLimited 直接跳 maxMs；连续 5 次失败进「冷却」，只响应手动下拉
- **触发**：APP_START（上次成功 >30min 才跑）· PULL_REFRESH（全量、重置退避）· WIDGET_TICK（只跑 schedule）· BACKGROUND
- **调度壳**：沿用现有 **AlarmManager + `ScheduleBackgroundRefresh`** 模式（E4），不引 WorkManager。`SyncEngine` 是纯 Kotlin 类（无 Android 依赖），可跑 JVM 单测 → 云端 CI 直接跑
- **网络条件**：schedule/grades 恒允许（体积极小）；theol/mail/venue 可设「仅 WiFi」（`NET_CAPABILITY_NOT_METERED`）

### 3.6 邮箱与场馆

- **邮箱**：`angus-mail`，`Folder.READ_ONLY`，只拉最近 30 天 ENVELOPE（不拉正文），UID 增量缓存；正文点开才拉。IMAP 独立授权码存独立 vault，与 SSO 凭据物理分离。凭据失效只影响 mail 域
- **场馆**：免登录公开页直抓，`domain.requiresLogin = false`，无 Auth 错误路径；1 小时即 STALE（预约余量时效敏感）

## 4. 功能路线图

### 4.1 THEIA 22 模块 → Android 承接 16（合并为 14 个交付模块）

砍掉 6 个：本地工作包（桌面文件工作流）· 模型辅助 AI 答题 · 提交准备（写操作）· 后台收信（Android 后台限制）· 学业顾问 Agent · Iris QQ 助手 / 本机 loopback API / 3D 外观。

保留的 THEIA 两条核心洞察：**空结果 ≠ 没有数据**（RefreshState 五态）· **单域失败不清空其它域**。

| **M4 工作台 + 企微** | 5 周 / 24 人日 | Dashboard 首屏 · 场馆/体测/学业工具/导出 · 企微链路（按 §5 判定）· TLS P2（远端 pin） | ≤100MB | **首屏 3s 出内容（无网同样达标）** · 企微 10 条逐条对照一致 · 30 天崩溃率 <0.5% |

**退出条件（阶段门禁）**：M1 = 登录/课表无 P0 级 bug 且 ≤30MB；M2 = 任何域「失败却清空旧快照」即回退；M3 = THEOL 3 门课以上崩溃 或 >70MB；M4 = 企微存在任何静默写操作 或 >100MB。

### 4.4 首屏信息架构

卡片顺序 = 「打开 App 最想看的 3 件事」：①下一节课（含地点）②今天要交什么 ③什么时候考试。

| 顺位 | 卡片 | 域 | 空态 | 失败态 | 过期态 |
|---|---|---|---|---|---|
| 1 | 下一节课（倒计时 + 教室） | schedule | 「今天没有课」（EMPTY_CONFIRMED） | 同步失败 + 重试 | 顶部黄条「来自 X 时刻」 |
| 2 | 今日待办（作业截止 + 企微待办） | theol + wecom | 「今天没有待办」 | 显示旧数据 + 时间 | 同上 |
| 3 | 考试倒计时（最近一场） | exams | NEVER 时显示「未同步」而非「没有」 | 同上 | 同上 |
| 4 | 未读通知 + 未读邮件 | notices + mail | 计数为 0 时整卡隐藏 | 只影响本卡 | 同上 |
| 5 | 校历条（第 X 周 / 假期） | calendar | 永不空（内置默认学期） | 不失败（纯本地） | 换季提示 |

**底部导航 4 tab**：工作台 · 课表（含成绩/考试）· 消息（通知+邮箱+待办）· 我的（账号/同步状态/学业工具/企微连接）。
不单设「工具」tab——低频功能收进「我的」，避免 5 tab 稀释高频路径；成绩/考试挂课表 tab（用户心智同源）。

### 4.5 明确不做（12 条）

1. **WebView 登录** — 硬约束；THEIA-Android 已验证死路
2. **Capacitor / RN 壳** — 同上 + 体积失控
3. **代抢课自动执行** — Android 后台不可靠 + 封号代价 > 抢课收益；只做查询 + 开抢前闹钟
4. **THEOL 作业代提交 / 答案写入** — 写操作破坏只读定位，误操作代价高于功能收益
5. **AI 学业顾问 / 模型辅助答题** — key 管理 + 体积 + 隐私三重成本，受众极窄；导出 JSON 已覆盖「喂给 AI」
6. **后台常驻 IMAP 轮询** — 后台限制下可靠性差 + 耗电口碑；前台刷新够用
7. **校园地图** — 已删高德 + MapLibre（16MB），体积不容；学校有官方渠道
8. **OCR 校历 / 培养方案** — 已删 ONNX（16MB）；文本解析 + PDF 链接够用
9. **本机 loopback API** — 桌面集成场景，Android 无消费方
10. **Iris QQ 机器人** — 凭据 + 常驻服务，单人无余力
11. **主题 3D 背景 / glb 模型** — 体积 + 与工具属性不符
12. **课表 PDF 导出** — 手机端无人用，流程脆弱（THEIA README 自称「估计没人用」）

## 5. 企业微信接入

先抓包确认链路，两套实现完全不同。

### 5.1 两条链路对比

| | A. 学校自建（`*.buct.edu.cn`） | B. 腾讯标准版（`open.work.weixin.qq.com`） |
|---|---|---|
| 凭据 | **复用 SSO Cookie** | corpId/secret 或 OAuth code |
| 登录 | SSO 换票一次 | 独立登录/扫码，需管理员配置可信域名 |
| 能拿 | 通知 / 待办 / 审批（只读，自己的）/ 通讯录（本部门）/ 校历 / 班车 | 应用消息 / 待办 / 日程（需服务端配合） |
| 学生可用性 | 高（有学号即可） | **几乎不可用**（无管理员凭据时一律砍掉，不做降级卡片） |
| 人日 | 6 + 3 抓包 | 4 |

### 5.2 抓包判定（3 步定链路）

1. 企业微信 → 工作台 → 打开学校应用，看入口 URL 域名：`buct.edu.cn` 系 → A；`qq.com` 系 → B
2. A：跳转是否经过 sidportal 登录页（是 → 可复用会话）
3. B：是否拥有 corpId/secret（否 → 砍掉企微功能）

抓包要点：HttpCanary（或 PC Fiddler + 学校 CA）过滤 `buct.edu.cn`；记录三要素 **Referer / Cookie / X-Csrf-Token**；curl 复放带自己 Cookie 直连成功 → 可原生接入；返回 401/跳扫码 → 走 B。

### 5.3 A 链路接线（关键：方向与 THEIA-Android 相反）

1. `BuctSsoSessionManager` 先完成 sidportal 登录
2. **WebView 打开企微 H5 入口一次**，注入 sidportal Cookie（domain=`.buct.edu.cn`）
3. 服务端 302 → 带 ticket 落到企微 H5 首页 → WebView CookieJar 出现企微域会话 Cookie
4. `CookieManager.getCookie(url)` 导出到原生 `PooledCookieJar`（与 AcademicSessionStore 同模式）
5. 之后全走 OkHttp + `BuctTlsTrustManager`；**WebView 不再出现**，除非会话失效重换一次

存储：企微 Cookie 独立 `WecomSessionStore`，与教务 session 生命周期解耦。失效判定 = 企微 API 401 → 静默重走 2-4。

### 5.4 合规红线（写进架构，不是写进文案）

不代打卡 · 不代审批 · 不自动回复 · 不静默上报。

- **架构保证**：App 内不存在企微写路径（不是 UI 隐藏，是没有代码）
- 指向写操作的链接只提供「在系统浏览器打开」
- 所有企微卡片固定「只读」角标
- 首次同步前弹一次确认（「只读取列表，不会替你提交任何内容」），记入 SharedPreferences 不再骚扰
- 企微域默认手动刷新

## 6. 工程与运维（详设见 plan-3）

### 6.1 模块化：保持单 module + 包级隔离

决定性理由：**全云端 CI 下，多 module 的主要收益（本机增量编译）完全兑现不了，成本（配置 ×2.5、R8 跨 module 保留更多死代码导致 APK 更大）全部照付。**

拆分触发条件（满足任意两条才评估）：① .kt > 30,000 行 ② 缓存命中后全量 CI > 15 min ③ feature 包 ≥6 且包依赖违规 ≥3 次/月 ④ 出现第二个构建变体。真要拆只拆 `:core-model` → `:campus-sync`，**不拆 `:feature-*`**。

包依赖规则（CI grep 校验，秒级）：

~~~text
ui/*     → store、session、model；禁止 source/* 里的 Http/Parse 类
sync/*   → source、store、session；禁止 ui
source/* → session、model；禁止 store、sync、ui；各域子包互不依赖
store/*  → model；禁止 source、sync、ui
session/*→ login、model；禁止一切上层
model/   → 零依赖
~~~

### 6.2 CI 体积门禁

现有 `.github/workflows/build-apk.yml`（75 行）改动 4 处：
① L57 `assembleRelease` 后插两个 step（体积门禁 + 明细报告） ② 删 L60 `List APKs` ③ `on:` 加 `pull_request: branches: [main]` ④ 保持 L36-42 cache

~~~yaml
      - name: APK size gate (100MB)
        run: |
          set -euo pipefail
          APK=$(find app/build/outputs/apk/release -name "*.apk" | head -1)
          BYTES=$(stat -c%s "$APK"); MB=$(awk "BEGIN{printf \"%.2f\", $BYTES/1048576}")
          echo "APK: $APK size: ${BYTES} bytes (${MB} MB)"
          if [ "$BYTES" -gt $((100*1024*1024)) ]; then
            echo "::error::APK ${MB}MB 超过 100MB 门禁"
            unzip -l -v "$APK" | sort -k1 -n -r | head -30
            exit 1
          fi
          echo "体积门禁通过 (${MB}MB <= 100MB)"
~~~

叠加规则：PR 体积 delta 用 `gh run download` 拉 main 基准 artifact 对比，**>500KB 必须在 PR 描述写归因**（新增依赖 / 资源各占多少）；禁止无归因合并。
Runner 4C16G，单 run 8-10min，月约 500min « 2000min 免费额度。

### 6.3 凭据存储

| 凭据 | 位置 | 说明 |
|---|---|---|
| 学号/密码 | **绝不落盘**，内存 `char[]` 用完 `fill('\0')` | 登录瞬间用完即弃 |
| SSO Cookie | 三 vault 文件之一，Keystore AES-256-GCM | alias `buct_sso_master_key` / `buct_mail_master_key` / `buct_wecom_master_key` |
| WebAuthn 凭据 | Android Keystore + `setUserAuthenticationRequired(true)` | 生物识别解锁后可用 |
| IMAP 授权码 | 独立 vault 文件 | 生命周期与 SSO 分离 |
| 企微 secret | 独立 vault | corpid 可明文，secret 必须加密 |

**不引 `androidx.security:security-crypto`**（E4 同源问题：基线没有，且该库仍带 alpha 状态）→ 自写 `KeystoreCipher.kt`（约 120 行，AES-GCM + 随机 IV，StrongBox 优先、TEE 回退）。密码库只在 Keystore，备份搬走的只是密文，故 `backup_rules.xml` / `data_extraction_rules.xml` 必须 exclude 三个 vault 文件。

生命周期：登录 → 存 Cookie（密码清零）→ SessionRenewer 读取 → 三类失效（会话过期 / 改密码 / 登出）→ 登出 `wipeAll()`（删文件 + 删 Keystore alias，不可逆）。

### 6.4 TLS：三级修复路线（v1 的「固定证书」表述作废）

| 级别 | 位置 | 现状 | 动作 | 阶段 |
|---|---|---|---|---|
| **P0** | `network/CourseApiClient.java` L54-72 + L214 | **信任所有证书 + 关闭 hostname 校验**（教务全部请求的唯一出口） | 换用 `BuctTlsTrustManager` 的 `sslSocketFactory()`，删 `hostnameVerifier((h,s)->true)` | **M1 必做** |
| P1 | `BuctTlsTrustManager.verifyChain` | 验签了，但不校验 SAN → 公共 CA 为任意域名签发的证书可通过兜底链 | 加 15 行 `isBuctDomain(leaf)`，SHA-256 域名后缀校验 | M2 |
| P2 | 无 pin | 全靠公共 CA 信任 | `config/tls-pins.json`（pins + backup_pins + not_after，GitHub Raw 下发，7 天缓存）；pin 失败拒绝 + pins 过期降级系统库 + 黄条 | M4 |

证书有期：GlobalSign 中间 2028-11-21 · R3 根 2028-01-28 · Sectigo E46 2038-01-18 · ZeroSSL 中间 2035-09-23。5 年内不炸，但**换 CA 那天没有远程止血手段 = 全量用户坏一天以上**——这就是 P2 存在的理由。

### 6.5 解析灰度与可观测

- **parserVersion** 进 Provenance，改解析必须 +1；升级后 UI 提示「数据由旧版解析器生成」
- **失败上报零后端**：只传 `domain + 失败类型 + 页面结构指纹`（规范化 HTML 的 SHA-256 前 16 hex：数字→N、中文块→C）。用户点「一键反馈」生成预填 issue 文本，你贴到 repo。**不引第三方 crash SDK**（会自动采集设备与上下文，与不传隐私冲突）
- **远端 kill switch**：`config/remote-flags.json`（commit 进 main 即全量生效，12h 缓存）→ 置 true 则客户端跳过该域 fetch，只读旧快照
- **本地阈值降级**：最近 20 次失败 ≥15 次（75%）→ 本机降级为「保留快照 + 标注，不发请求」。本地阈值只降本机，全局 kill 只由远端下发，两级不混
- **诊断包**：设置 → 诊断 → 导出 zip（各域 parserVersion / RefreshState / 失败统计 / 脱敏 HTML 片段 2KB）

### 6.6 发布与回滚

- 版本：`versionCode = major*10000 + minor*100 + patch`，`app/version.properties` 静态控制（现有机制）
- 渠道：**只有 vTag 是用户渠道**，`ci-N` 仅自测——CI 临时签名与正式签名不同，用户装错会无法覆盖升级
- 强制更新：`config/version.json` 的 `forceUpdate + minVersionCode`，仅用于「解析全崩无法热修」或安全漏洞
- **回滚单位是数据域，不是 APK**：

~~~text
T+0~10   config/remote-flags.json 把崩的域 kill=true → commit → 全量 12h 内停止抓取
T+10~20  本地验证旧快照路径（飞行模式开 App，UI 正常显示旧数据）
T+20~30  小改 → 修 parser +1 正常发版；大改 → 保留 kill + issue 置顶 + 排期
~~~
