# 签名接入

CI 已支持两种签名：**正式签名（推荐）** 与 **临时签名（兜底，仅够自测）**。
有正式签名的 secrets 就用正式签名，没有就退回临时签名并在 CI 里打 warning。

临时签名的 APK 不能给用户安装后升级——签名不同，覆盖安装会失败。

---

## 一、需要配置的 4 个 Repository secrets

| Secret 名 | 内容 |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | 你的 `.jks` 文件的 base64（单行，无换行） |
| `ANDROID_STORE_PASSWORD` | keystore 密码 |
| `ANDROID_KEY_ALIAS` | 密钥别名 |
| `ANDROID_KEY_PASSWORD` | 密钥密码（多数情况下与 store 密码相同） |

位置：仓库 → Settings → Secrets and variables → Actions → New repository secret。

## 二、把 .jks 转成 base64

PowerShell（Windows）：

```powershell
[Convert]::ToBase64String([IO.File]::ReadAllBytes("C:\path\to\release.jks")) | Set-Content -NoNewline release.jks.b64
Get-Content release.jks.b64 | Set-Clipboard
```

Git Bash / WSL：

```bash
base64 -w0 release.jks > release.jks.b64
```

把 `release.jks.b64` 的内容整行粘进 `ANDROID_KEYSTORE_BASE64`。

> 注意：base64 必须**单行无换行**。GitHub 的 secret 输入框会保留换行，因此务必用 `-w0`（bash）或 `-NoNewline`（PowerShell）。

## 三、如果你还没有 keystore

```bash
keytool -genkeypair -v -keystore release.jks -alias buctone \
  -keyalg RSA -keysize 4096 -validity 36500 \
  -dname "CN=BUCT One, OU=Personal, O=Personal, L=Beijing, ST=Beijing, C=CN"
```

`-validity 36500` 是 100 年——**不要让签名过期**，过期后无法发布更新。

## 四、keystore 的保管（比配置更重要）

1. **离线双备份**：一份在本机加密盘，一份在离线 U 盘/纸质密码本
2. **绝不进仓库**：`.gitignore` 已排除 `*.jks` / `*.keystore` / `*.pem`
3. **绝不贴聊天记录**：keystore 泄露 = 他人可发布冒名更新
4. 丢了 keystore = 已安装用户**永远无法升级**，只能换包名重发（等于重来一遍）

## 五、验证签名是否生效

CI 跑完后看 `Prepare signing` 这一步的日志：

- `签名：正式（secrets 已配置）` → 正确
- `::warning::未配置正式签名 secrets` → 还在用临时签名，只能自测

下载 APK 后本地校验：

```bash
"$ANDROID_HOME/build-tools/37.0.0/apksigner" verify --print-certs app-release.apk
```

## 六、签名与包名的关系

| 项 | 值 |
|---|---|
| `applicationId` | `com.buct.one` |
| `versionCode` | 从 1 开始（当前 1） |
| `versionName` | 从 0.1.0 开始 |

这是**全新应用**，与旧版「北化课表」（`com.tyust.course`）完全独立，可以同时安装。
旧版用户的应用内升级**不会**迁移到这个新 App——需要重新安装。
