# BUCT One · 消息推送与智能提醒规划

> 本文档面向 `v0.4.x` 阶段规划，立足单人维护、隐私底线与国产 Android ROM 生态实际，制定渐进式、无凭据上云风险的提醒与推送架构方案。

---

## 一、现状盘点（截至 v0.3.4）

目前已落地的提醒基础设施：
1. **课程课前提醒（`ScheduleReminderScheduler.kt`）**：基于本地课表快照，通过 `AlarmManager.setExactAndAllowWhileIdle` 触发课前本地通知（通知渠道 `NotificationManager.IMPORTANCE_DEFAULT`）。
2. **考试倒计时提醒（`ExamReminderScheduler.kt`）**：复用 `AlarmManager` 精确闹钟触发，使用高优通知渠道（`NotificationManager.IMPORTANCE_HIGH`）。
3. **系统权限自检入口（`SettingsRoute.kt`）**：已在「我的」页集成 `NotificationManagerCompat.areNotificationsEnabled()` 与 `AlarmManager` 精确闹钟权限检测卡片。

**尚未具备的能力**：
- 尚未引入 `WorkManager` 周期后台轻量增量拉取；
- 作业/测验 DDL、图书馆还书倒计时、校园卡余额预警、宿舍电费余额预警、教务调停课新消息、新出成绩与重要新邮件均未接入通知提醒；
- 无跨端/服务端推送机制（如自建网关或全校公告广播）。

---

## 二、红线与安全设计约束

1. **绝不托管个人校内凭据上云**：绝不允许为了做“云端消息推送”，让服务器代存用户的统一身份认证学号/密码、Cookie、成绩或流水去后台代登轮询。所有涉及个人私有校内域数据的拉取，**必须在手机端本地完成**。
2. **绝不引入第三方商业推送 SDK**：严格遵守项目安全约定，禁止集成个推、极光、友盟、Firebase 等第三方商业推送/统计 SDK。
3. **尊重用户打扰边界与续航**：
   - 默认只对「确定高价值事件」触发推送（DDL、调停课、新出成绩、低于阈值的余额）；
   - 严格设置夜间静默时段（如 `23:30 – 07:30`）与本地幂等去重记录，绝不重复轰炸同一条事件。

## 三、分阶段演进路线

### 第一阶段：纯本地双引擎智能提醒（首选主力，零服务端隐私风险）

通过「本地已知截止事件精确闹钟」+「`WorkManager` 低频后台增量轮询」双引擎协同，无需任何后端改造即可覆盖 90% 的日常刚需：

#### 引擎 A：零耗电确定性事件闹钟（复用现有 `AlarmManager` 链路）
适用数据：**本地同步完成后截止时间已经固定下来的事件**（即使 App 被系统杀后台，闹钟到点也能准时弹出，不耗费后台常驻电量）：
- **北化在线作业 / 在线测验 DDL**：每次 `TheolSyncService` 同步完成后重算所有未完成且未隐藏的作业/测验，默认在截止前 **24 小时**、**3 小时**注册闹钟（支持用户自定义提前量）。
- **图书馆在借到期提醒**：每次 `PortalSyncService` 图书馆列表同步成功后，在应还日前 **3 天**与**当天上午 09:00**注册本地闹钟提醒。

#### 引擎 B：`WorkManager` 低频增量巡检（`androidx.work:work-runtime-ktx`）
适用数据：**需要联网拉取才知晓变动的新事件**：
- **教务系统调停课与新消息（`JwNoticeSyncService`）**：对比新旧消息 ID，仅对从未通知过的未读个人消息（调停补课、考试安排）触发通知，跳转 `JwNoticeActivity`。
- **新出成绩通知**：对比本地已缓存成绩单课程集合（课程号+学期唯一键），出现新成绩时通知提醒查看 GPA 与分数。
- **宿舍电费低余额预警（`ElectricitySyncService`）**：仅当用户**已同意学号防滥用共享授权**且**已绑定房间**时随巡检静默刷新（复用服务端 15 分钟缓存 + 限流安全窗），余额首次跌破用户设定 `lowBalanceThreshold` 时推送一次提醒，直到下次充值恢复阈值之上才重置去重标记。
- **校园卡余额低于阈值（`CardSyncService`）**：仅当 `canAutoSync()` 为真（开启了记住密码且凭证有效）时低频检查，低于阈值提醒一次。
- **校园邮箱重要未读提醒（`MailSyncService`，默认关闭需手动开启）**：避免广告邮件骚扰，可选仅对含特定关键词（如「教务」「通知」「奖学金」「缴费」）的新收件箱邮件提醒。

**调度与省电防轰炸策略**：
- **周期频率**：采用 `PeriodicWorkRequest`（周期 4~6 小时，要求 `NetworkType.CONNECTED`、`setRequiresBatteryNotLow(true)`）。
- **夜间免打扰窗口**：Worker 在本地判断当前时间为 `23:30 – 07:30` 时仅静默更新快照不弹响通知（次日早晨恢复时段再按最新状态提醒），或在可配置免打扰时间内推迟。
- **去重状态表（`ReminderDedupStore`）**：落盘记录 `(domain, itemKey, ruleType, notifiedAt)`；如电费低余额仅在从「高于阈值 → 低于阈值」状态跳变时触发一次；作业交完后在下次同步自动撤回待触发 `PendingIntent`。
- **国产 ROM（HyperOS / OriginOS / ColorOS）兼容性补偿**：
  - 国产 ROM 后台杀死 App 后 `WorkManager` 可能被延迟到亮屏解锁才唤醒，因此额外在**用户每次主动打开 App / 下拉刷新成功**或**系统充电窗口**复核一次增量变更并补排闹钟，明确不在前台做无意义保活拉流。

#### 通知渠道划分（Android 8.0+）
| Channel ID | 名称 | 重要程度 | 覆盖场景 |
| :--- | :--- | :--- | :--- |
| `reminder_urgent` | 学业与紧要通知 | `IMPORTANCE_HIGH` | 课前提醒、考试倒计时、教务调停课、3h 临期 DDL |
| `reminder_digest` | 账单与日常提醒 | `IMPORTANCE_DEFAULT` | 24h DDL、新出成绩、图书到期、电费/校园卡低余额 |
| `reminder_mail` | 重要校园邮件 | `IMPORTANCE_LOW` | 可选关键词匹配未读新邮件 |

#### 设置页交互设计（「我的 → 提醒与通知」）
- 复用已有「通知权限 / 精确闹钟权限」状态自检横幅；
- 提供总开关与按场景分项开关（作业 DDL、调停课消息、新出成绩、图书到期、宿舍电费低于阈值、校园卡低于阈值、重要新邮件）；
- 提供 DDL 提前量（`24h / 12h / 3h / 1h` 多选）、校园卡低余额阈值（`10 / 20 / 30 / 50 元`）、夜间免打扰时段开关与「发送一条测试通知」验证按钮。

### 第二阶段：无隐私云端推送通道评估（按需扩展）

针对少数「**不依赖用户私人校内凭据、却希望第一时间触达**」的场景，可考虑结合自托管基础设施补充轻量推送，**仍保持零商业 SDK**：

1. **适用场景**：
   - **全校公共重要公告 / 新版强制更新提醒 / 抢课关键时间提醒**：纯公开只读静态公告（可由 `update.buct.one` / Cloudflare Workers 提供 JSON 轮询或轻量 SSE/UnifiedPush）。
   - **宿舍电费「服务端定时低余额订阅」（可选进阶）**：因电费网关 `ele.buct.one` 本身在服务端运行且拥有全校房间公开余额查询能力，若用户手动提交「仅房间号 + 阈值」（无需学号密码），网关可通过自建通知渠道或匿名 Topic（如自托管 `ntfy` + **UnifiedPush** 标准协议）推送低余额预警——App 被彻底杀死也能由统一推送通道秒级唤醒，且完全不接触学校认证凭据。
2. **技术选型原则**：
   - 若未来做离线推送，优先支持标准 **UnifiedPush**（配合本地通知分发或自托管极简 `ntfy` 实例，无厂商全家桶依赖），或继续以 App 启动/前台低频拉取 `update.buct.one/announcements.json` 兜底公共通知。

## 四、APK 体积与 CI 约束自查

- **依赖体积预算**：
  - 第一阶段引入 `androidx.work:work-runtime-ktx`（含必要传递依赖）预计增加 APK 体积 **约 0.35 ～ 0.55 MB**，远低于 `build-apk.yml` 80 MB 预警线与 100 MB 硬门禁，无需任何 NDK 或本地编译工具链插件。
- **分层规范遵循**：
  - `ReminderRuleEngine` 与 `ReminderDedupStore` 等纯状态/模型放在 `com.buct.one.data.model` / `store`；
  - `WorkManager` Worker 与通知调度放在 `com.buct.course.schedule` / `reminder`（UI/Android 平台层调用 `sync/`，反向不污染 `sync/` 与 `source/`）。

## 五、第一阶段开发落地顺序（待确认后开工）

1. **Step 1**：新增 `ReminderSettings` + `ReminderDedupStore` 与各通知渠道注册工具。
2. **Step 2**：实现引擎 A —— 在 `TheolSyncService`、`PortalSyncService` 同步成功回调后串联作业/测验 DDL 与图书到期本地 `AlarmManager` 闹钟（参照 `ExamReminderScheduler` 模式）。
3. **Step 3**：在 `app/build.gradle` 引入 `androidx.work:work-runtime-ktx`，实现引擎 B —— `CampusBackgroundSyncWorker`（串行轻量检查教务新消息、新成绩、电费、校园卡并按去重表派发通知）。
4. **Step 4**：在「我的 → 提醒与通知」落地上线分项开关、夜间免打扰、阈值设定与测试通知按钮，补齐去重逻辑单测并走 GitHub Actions CI 验证体积与单测。
