## 4. 视觉方向（这是本项目最容易被做歪的地方）

### 4.1 目标形态

**所有容器都是悬浮胶囊 + 液态玻璃**。不是只有底部导航——卡片、筛选器、输入框、按钮、提示条、分段控件，一律胶囊化且与背景留白。

参考：上游同校工作台的真机截图（在对话里，色的采样值见下）。

```
画布   #EEF2FA → #E2E7F5 → #ECE2EF → #E4EDF5   （蓝→紫→青的高亮渐变，亮度 >88%）
玻璃   白色 alpha 0.46（普通）/ 0.62（强），描边 #F0FFFFFF
文字   #10151F / 0xB8 / 0x8A 三档
主色   #0A84FF
课程块 粉红 #FAD4D1 · 淡紫 #E8D0EA · 淡蓝 #CFE4F7 · 蓝紫 #D0D6F8 · 卡其 #E6DFCF
```

**关键判断**：目标是「浅色、低对比、淡彩」，不是「深色玻璃 + 高对比」。这条走错过三轮（M3 → Linear 暗色 → 深色玻璃），不要再走回去。

### 4.2 胶囊规格（已代码化）

`ui/system/Capsule.kt` 里 `Capsules` 对象，8 种预设：

| 名称 | 高度 | 圆角 | 用途 |
|---|---|---|---|
| Dock | 68dp | 34dp | 底部悬浮坞 |
| Card | 自适应 | 28dp | 信息卡 |
| CardHero | 自适应 | 30dp | 主卡 |
| Chip | 36dp | 18dp | 筛选器 |
| Field | 52dp | 26dp | 搜索/输入 |
| Pill | 44dp | 22dp | 按钮 |
| Segment | 40dp | 20dp | 分段控件 |
| Toast | 48dp | 24dp | 提示条 |

规则：**高度一半即圆角**。新组件从这里取 spec，不要自己写 `RoundedCornerShape(16.dp)`。

### 4.3 玻璃三档（重要）

| 档 | 实现 | 覆盖 | 状态 |
|---|---|---|---|
| A | `com.github.skydoves:cloudy` 的 `Modifier.liquidGlass()` 真折射 + 色散 | API 33+ | **未做** |
| B | `dev.chrisbanes.haze` 背景模糊 | API 31+ | 未做 |
| C | 纯 alpha + 0.5dp 高光边 | 全版本 | **M1 现状** |

现在跑的是 C 档。所以真机上玻璃会比 `docs/mockups/dashboard.html` 原型「平」——这是预期，不是 bug。
A 档要等 M2，因为要处理 API 分支和性能降级，调试成本高。

## 7. 踩过的坑（别重踩）

**1. compileSdk 必须写 `'android-37.0'`**
SDK 目录自 API 37 起用次版本号命名，只有 `platforms/android-37.0`，没有 `android-37`。写成 `compileSdk 37` 会报 `Failed to find target with hash string 'android-37'`。

**2. gradlew 可执行位**
Windows 检出时 git index 不记 100755，CI 会报 `./gradlew: Permission denied`（exit 126）。
已修：`git update-index --chmod=+x gradlew` + workflow 里 `chmod +x ./gradlew` 双保险。

**3. git push 直连 GitHub 不通**
必须配代理（见第 2 节）。第一次推会失败，配完重试即可。

**4. .gitignore 曾把 docs/ 排除**
上游模板里有 `/docs/*`，导致规划文档一直没进版本控制（`git status` 干净但 `git ls-files` 数不出来）。已删该行。如果发现新文件「明明存在但没提交」，先查 `.gitignore`。

**5. 子代理不稳定**
派过 3 次 UI 规划子代理：`qwen3.8-max-0902` 失败、`claude-opus-5-5-high` 失败、`glm-5.3` 成功。**注意：`newapi-private` 下没有 `qwen4max`**，最接近的是 `qwen3.8-max-0902`。派子代理时优先用 glm-5.3。

**6. 未使用的 import 只是警告**
Kotlin 不会因为 unused import 编译失败，别为此大改。

**7. 中心凸起钮被坞裁掉一半**
坞体用了 `clip(RoundedCornerShape(34.dp))`，如果中心钮放在坞内部的 Row 里，
超出坞边界的部分会被裁掉。**坞体与中心钮必须是 Box 下的兄弟节点**，
中心钮用 `Modifier.align(Alignment.TopCenter).offset(y = (-16).dp)` 浮到坞外。
这个问题 HTML 原型看不出来（CSS 的 overflow 行为不同），只有真机能发现。
