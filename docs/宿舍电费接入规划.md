# BUCT One · 宿舍电费查询功能 App 接入规划

> 关联后端仓库：`STAR-10086/buct-electricity-worker`｜服务端入口：`https://ele.buct.one`
> 本文档用于沉淀移动端（`buct-one`）接入宿舍电费查询网关的协议约定、分层设计、UI 交互与上线检查清单。

---

## 一、背景与前置准备

### 1.1 网关架构现状
- 学校企业微信「校园卡服务」（`https://mcard.buct.edu.cn/channel/queryResEle`）在有活跃 `JSESSIONID` + `openid` 时，可 24 小时免宵禁查询全校三校区宿舍电费/剩余电量。
- 为避免在公网或客户端暴露个人 `openid` / `JSESSIONID`，已将网关以零运行时依赖的 Node.js 22 Docker 服务部署于 VPS，前端通过 Cloudflare Tunnel + Cloudflare for SaaS 接入 **`https://ele.buct.one`**，管理后台则隔离在独立的 Cloudflare Zero Trust 域名并开启 `RS256` JWKS 验签与 `ALLOWED_ADMIN_HOST` 隔离。
- 网关内置每 8 分钟一次（`480s`）的 `/channel/getXiaoQuList` 保活心跳，并强制实施全校 10,028 间宿舍白名单校验、15 分钟结果缓存及单设备回源限流。

### 1.2 App 端上线部署配置确认项
- [x] **24h 跨天保活确认**：已在后台面板确认学校网关保活心跳可用。
- [ ] **VPS 开启 App 学号签名鉴权（上线必填）**：服务端 `STAR-10086/buct-electricity-worker` 已实现 `X-Student-Id` 绑定签名、按学号统计查询次数与 `/admin` 拉黑管理；在 VPS 更新拉取最新代码后，于 `.env` 配置 `REQUIRE_APP_SIGNATURE=true` 与 `APP_SIGN_SECRET=<随机密钥>` 并重启容器，同时在 `buct-one` GitHub Actions Secrets 添加同名值 `ELECTRICITY_SIGN_SECRET`。

## 二、网关接口与请求约定

### 2.1 接口清单（公网直连 `https://ele.buct.one`，不走 WebVPN）

1. **`GET /v1/health`**（网关健康检查）
   ```json
   {
     "ok": true,
     "alive": true,
     "updatedAt": 1795354606,
     "lastHeartbeatAt": 1795355115,
     "totalRooms": 10028
   }
   ```
   - 当 `alive == false` 时，App 应保留上次成功缓存余额并显示提示「电费查询服务维护中，以下为历史快照」（严格遵守失败不覆盖旧 `data` 铁律）。

2. **`GET /v1/rooms`**（全校三校区房间字典，带 `Cache-Control: public, max-age=86400`）
   - 结构：`{ factorycode, crawledAt, campuses: [{ schoolid, name, hasMeterType, buildings: [{ buildingid, name, floors: [{ floorid, name, rooms: [{ roomid, name, meterType? }] }] }] }] }`
   - 校区差异：
     - **昌平新校区（`schoolid = "1503634598"`）**：余额单位为 `元`（如 `"100.00 元"`）。
     - **东校区（`schoolid = "ws_东校区"`）**：同一宿舍包含 `meterType = "照明"`（如 `ws_103001`）与 `meterType = "空调"`（如 `ws_1103001`）两块电表，单位为 `kWh`。
     - **西校区（`schoolid = "ws_西校区"`）**：单表，单位为 `kWh`。
   - **选型建议**：将精简后的 `rooms.json`（gzip 约 48 KB，原始约 587 KB）直接内置为 `app/src/main/assets/electricity_rooms.json` 实现 0ms 本地离线级联选择；后续可按需支持通过 `/v1/rooms` 的 `crawledAt` 做轻量增量更新。

3. **`GET /v1/electricity?schoolid={schoolid}&roomid={roomid}`**（查询指定电表）
   - **成功响应（HTTP 200）**：
     ```json
     {
       "schoolid": "1503634598",
       "roomid": "CCPS.BUCT.B0601.F01.R0102",
       "campusName": "昌平新校区",
       "buildingName": "樱花苑1号楼",
       "floorName": "一层",
       "roomName": "102",
       "meterType": "",
       "balanceText": "100.00 元",
       "balanceValue": 100.0,
       "unit": "元",
       "accountStatus": "1",
       "queriedAt": 1795354800,
       "fromCache": false
     }
     ```
   - **关键错误码处理**：
     - `HTTP 400`：房间不在白名单（需提示重新选择绑定宿舍）。
     - `HTTP 429`：触发单设备回源冷却（含 `Retry-After` 秒数），提示「更换新房间查询过于频繁，请 X 分钟后再试」，不清空旧数据。
     - `HTTP 502`：电表不在线或上游异常。
     - `HTTP 503`：网关凭证维护中（`alive=false`）或上游并发已满，保留旧缓存余额并展示温和提示。

### 2.2 必传请求头与防误伤/防脚本规则
- **`User-Agent`**（必须设置正常移动端 UA）：
  - 实测 Cloudflare 边缘节点会对裸 `Python-urllib` / 默认空 UA 返回 `error code: 1010` 拦截；`OkHttp` 默认自带 `okhttp/4.x` 也建议显式覆盖为与 `UmamiTracker.buildAndroidUserAgent()` 一致的浏览器形态 UA（如包含 `Mozilla/5.0 (Linux; Android ...) Chrome/... Mobile Safari/537.36 BuctOne/...`）。
- **`X-Client-Id`**（必需）：
  - 复用 `UmamiTracker` 相同的随机安装标识策略（独立 `UUIDv4`，绝不采集学号或硬件指纹），避免北化校园网共用 NAT 出口 IP 时互相消耗配额。
  - 网关对同一个房间保留 **15 分钟（900s）缓存**（命中缓存不扣配额），对单个 `X-Client-Id` 仅限制**每 10 分钟最多 3 次未命中缓存的新房间回源**（足以支持东区同学同时刷新照明 + 空调双表）。
- **`X-Student-Id` + 轻量请求签名（与服务端防滥用机制绑定）**：
  - `X-Student-Id`：当前登录同学的有效学号（仅统计个人查询次数并在发生恶意扫楼滥用时用于管理员后台拉黑封禁，绝不上传密码、姓名、Cookie 或流水；演示模式及未同意隐私声明前禁止调用）。
  - `X-Timestamp`：当前秒级 Unix 时间戳（允许误差 ±300s）。
  - `X-Sign`：`SHA-256("${studentId}:${clientId}:${roomid}:${timestamp}:${appSignSecret}")` 的 64 位小写十六进制字符串；若学号或签名不合法返回 `HTTP 401`，若学号被管理员拉黑返回 `HTTP 403`。

## 三、App 分层设计与工程约束（严格对齐 `AGENTS.md`）

### 3.1 包结构与单向依赖检查
严格满足 CI `Package dependency rules`：
```text
model/    ← 零外部 import
store/    ← model
source/   ← session、model（禁止依赖 store、sync、ui 及其他 source 子包）
sync/     ← source、store、session（禁止依赖 ui）
ui/       ← store、session、model（禁止 import source/*）
```

建议新增文件清单：

1. **`app/src/main/java/com/buct/one/data/model/ElectricityModels.kt`**（零外部依赖）
   - `ElectricityRoomTarget`：`schoolid`、`campusName`、`buildingid`、`buildingName`、`floorid`、`floorName`、`roomid`、`roomName`、`meterType`
   - `ElectricityReading`：`target`、`balanceText`、`balanceValue: Double?`、`unit`、`accountStatus`、`queriedAtEpochSec`、`fromCache`
   - `ElectricitySnapshot`：支持保存主绑定房间及**同宿舍多表绑定**（`targets: List<ElectricityRoomTarget>`、`readings: List<ElectricityReading>`，方便东校区同时绑定「照明 + 空调」两块表）与 `lowBalanceThreshold: Double`（默认 `20.0`），并随 `DomainSlice<ElectricitySnapshot>` 携带 `provenance`（`FRESH` / `EMPTY_CONFIRMED` / `FAILED_FALLBACK` / `NEVER`）、`lastError`、`capturedAt` 与 `parserVersion`。

2. **`app/src/main/java/com/buct/one/data/store/ElectricityStore.kt`**
   - 参考 `CardStore.kt` 实现原子写盘（`AtomicFile` / 临时文件 rename）与内存 `StateFlow` 缓存。
   - **四条铁律自查**：
     - 同步失败时仅更新 `refreshState` 与 `lastError`，**保留所有旧 `readings` 余额**；
     - `NEVER`（从未绑定房间或从未拉取）与「当前绑定房间余额为 0 / 停电」严格区分展示；
     - `parserVersion = 1` 起步；
     - `capturedAt = maxOf(old.capturedAt, newCapturedAt)` 单调不减，防止系统时钟回拨。

3. **`app/src/main/java/com/buct/one/data/source/electricity/ElectricityClient.kt` & `ElectricityParser.kt`**
   - 走 `BuctTlsTrustManager`（**禁止**信任全证书，**禁止**接入 `BuctWebVpnInterceptor`，`ele.buct.one` 为公网可达域名）；
   - `OkHttpClient` 合理配置超时（`connectTimeout = 10s`、`readTimeout = 12s`）；
   - 通过方法参数接收 `clientId: String`、`studentId: String` 与 `signSecret: String`（不直接跨层 import `UmamiTracker` 或 `UserManager`）；
   - `ElectricityParser` 保持纯函数解析并补齐离线 JUnit 单测样本。

4. **`app/src/main/java/com/buct/one/data/sync/ElectricitySyncService.kt`**
   - 编排多表顺序/并发刷新（东区同一宿舍照明 + 空调 2 次请求均在单设备 3 次限额内）；
   - 控制前端手动刷新节流提示（例如当某房间 `queriedAt` 距当前不足 60s 时可直接提示缓存最新值或允许按需刷新由边缘缓存兜底）。

## 四、UI 与工作台交互规划

### 4.1 独立一级页面：`ElectricityActivity`
- 遵循 `AGENTS.md` 规范：新建独立 `ComponentActivity`（`ElectricityActivity`），内部使用 `GlassWindowHost` 承载并注册到 `AndroidManifest.xml`，确保拥有完整 Android 14+ 跨 Activity 预测性返回手势（受 `AppearanceSettingsManager.predictiveBackEnabled` 控制）。
- 页面内二级内容（如「切换 / 绑定宿舍」级联选择器、「低电量提醒阈值设置」）使用 `GlassSubpage` 承载。
- **宿舍绑定体验优化**：
  - 本地加载 `assets/electricity_rooms.json` 进行 `校区 → 楼栋 → 楼层 → 房间` 级联选择；
  - 对东校区（`hasMeterType == true`）提供筛选或**一键自动配对同房间照明 + 空调两块电表**（例如选中 `301照明` 时自动匹配同层同名 `301空调`），减少手动选两次的繁琐。
  - 在首次进入 `ElectricityActivity` 时展示独立「学号共享与防滥用说明」同意门禁页，并在查询主页、绑定设置页顶部常驻提示 **「查询电费将与开发者共享学号以避免滥用」**（支持一键撤回同意并清空本地宿舍绑定与缓存）。

### 4.2 工作台卡片：`DashboardModuleId.ELECTRICITY`
- 在 `DashboardRoute.kt` 新增模块枚举 `ELECTRICITY`（支持 `1×1`、`2×1` 常见尺寸）：
  - **未绑定房间（`NEVER`）**：引导点击前往绑定宿舍，不展示 `0.00`。
  - **昌平 / 西区单表**：大号液态玻璃数字突出显示剩余电费/电量（如 `100.00 元` / `120.00 kWh`）+ 宿舍简称 + 更新时间。
  - **东区双表**：分两行紧凑展示 `照明 80.00 kWh` 与 `空调 45.50 kWh`。
  - **低余额预警**：低于用户设定阈值（默认如昌平 `< 20 元`、东/西区 `< 20 kWh`）时切换醒目琥珀/红色提示徽标。

### 4.3 后续扩展（随《规划.md》阶段一第 6 项推进）
- 结合本地轻量 `WorkManager` 周期拉取（避开深夜与高频），余额低于阈值时推送本地通知提醒及时去微信/企微购电；
- 视需要复用现有无标题玻璃桌面小组件框架增加「宿舍电费」迷你小组件。

## 五、安全、隐私与体积预算

- **隐私边界**：仅向 `ele.buct.one` 上报经用户明确同意共享的学号（`X-Student-Id`，严格限定用于统计个人查询次数与滥用拉黑防护）、随机匿名 `X-Client-Id` 与待查宿舍编号，绝不上传统一身份认证密码、真实姓名、校园卡密码、Cookie 或消费流水；演示账号不开启该能力，且用户可随时在页面内撤回同意。
- **依赖与体积**：零新增第三方 SDK / 依赖库，复用现有 `OkHttp`、`org.json` 与 `java.security.MessageDigest` 计算 SHA-256；内置房间字典经压缩后仅约 **48 KB**（打包进 APK 资源后增加 < 0.1 MB，完全不触发 80MB 预警线）。
- **CI 检查**：遵循约定不跑本地全量 Gradle 构建，通过静态包依赖检查与隐私关键字排查后交付 GitHub Actions `check.yml`（单元测试 + 代码约束检查）与 `build-apk.yml` 验证。
